# LifeTrack 图形界面使用教程

LifeTrack 会在这台 Mac 上定时读取 Apple“查找”中设备的最后已知位置，并归档已经同步到本机的新短信、iMessage 和通话记录。位置和通讯内容均加密保存在本机；同一 GUI 可以查看地图轨迹和通讯归档。

日常使用不需要终端，也不需要输入命令。

> 这是个人研究用工具，依赖 Apple 未公开的 iCloud Web 接口。Apple 可能改变接口；它不能代替安全、救援或实时定位服务，也不会响铃、标记丢失或抹除设备。

## 打开应用

在 Finder 中打开“个人收藏 → 应用程序”，双击 **LifeTrack**。

应用实际安装在：

```text
~/Applications/LifeTrack.app
```

这是完整的独立应用包，内部包含 Python 3.12 运行时、iCloud 客户端和后台采集器，不再依赖项目目录或 `.venv`。轨迹数据库和设置仍按 macOS 规范保存在用户的 Application Support 目录中。

当前安装包针对这台 Apple Silicon Mac 构建并采用本地签名。它可以脱离源代码目录运行；若要公开分发给其他用户，还需要 Apple Developer ID 签名、公证和通用架构构建。

建议把它拖到程序坞，之后直接从程序坞打开。

## 开始记录

1. 打开 LifeTrack。
2. 点窗口右上角的 **记录设置**。
3. 在“记录设备”中勾选要记录的设备，再点 **应用设备选择**。
4. 点 **开始记录**。

窗口右上角显示绿色“正在记录”即表示后台记录已经启动。关闭地图窗口不会停止记录；重新登录这台 Mac 后，后台记录会自动启动。

如果没有设置总运行时间，记录会一直持续，直到你手动停止。Mac 关机、休眠或断网期间无法采集。

## 设置记录间隔

在 **记录设置 → 采集间隔** 中选择快捷值：

- 1 分钟
- 5 分钟（推荐）
- 10 分钟
- 30 分钟

也可以选择“自定义…”，输入 1–1440 分钟之间的任意整数。

选择后点 **应用间隔**。如果正在记录，后台服务会自动重新载入新间隔。

## 运行状态与异常通知

“记录设置”的运行状态区显示最近成功、最近一次尝试、下次预计采集、最新位置延迟、最近错误，以及每台设备最后位置时间。网络错误发生时，下次预计采集会按照后台退避策略相应延后。

首次启动 0.4.0 或更高版本时，请允许 LifeTrack 发送通知。Apple 认证失效、位置采集异常、未选择设备、通讯归档权限缺失或后台组件异常停止时，LifeTrack 会发送 macOS 通知；相同错误连续发生时只提醒一次，恢复正常后再次发生才会重新提醒。

收到认证失效通知后，在“记录设置 → Apple 账户”中完成重新认证。如果后台原本正在运行，认证成功后 LifeTrack 会自动重启服务并恢复位置采集。

间隔越短，对 Apple 接口的请求越频繁，也更容易遇到限流。采集间隔并不代表 Apple 一定会以相同频率更新设备位置；只有 Apple 返回新的位置时间戳时，LifeTrack 才会保存一个新轨迹点。

## 查看运行状态

打开 **记录设置 → 运行状态**，可以查看：

- 后台服务是否正在记录。
- 最近一次成功采集时间。
- 最近一次尝试的时间和结果。
- 已保存的位置点总数。
- 当前历史数据的起止时间。

点 **刷新状态** 可以立即重新读取这些信息。

## 停止记录

打开 **记录设置**，点 **停止记录**。

停止后，已有历史轨迹仍然保留。以后点 **开始记录** 会接着原有历史继续记录。

## 选择设备

打开 **记录设置**：

1. 勾选或取消勾选设备。
2. 至少保留一台设备。
3. 点 **应用设备选择**。

需要从 Apple 重新获取列表时，点 **刷新设备**。iPhone、iPad、Mac 等设备通常可以显示；AirPods 可能出现在列表中但不一定返回位置。当前不支持 AirTag 的加密报告。

## 在地图上查看轨迹

- 在左侧选择设备。
- 在左上角选择 1 小时、6 小时、24 小时、48 小时、7 天、自定义或全部历史。
- “地图坐标”默认选择 **中国大陆自动校正**，会对大陆地区的位置应用 WGS-84 → GCJ-02 地图显示转换，用于消除 Apple 私有接口坐标与中国大陆 Apple 地图之间固定数百米的偏移；境外坐标不会转换。如果不需要校正，可切换为 **原始坐标**。
- 选择 **自定义** 后，分别设置开始和结束日期、时间；地图只显示定位时间落在该区间内的点。
- 蓝线是按设备位置时间排列的轨迹。
- 拖动窗口底部的滑块，可以逐点回看轨迹。
- 点地图上的位置点，可以查看设备时间、采集时间、定位精度、电量，以及 Apple 是否把它标记为旧位置。
- 点左下角 **重新载入**，即可读取后台刚写入的新位置。

底部信息栏中的两个时间含义不同：

- **位置**：设备产生该位置，或 Apple 报告该位置的时间。
- **采集**：这台 Mac 从 Apple 取回并保存该位置的时间。

设备离线、Apple 返回旧位置或接口存在延迟时，两个时间可能相差较大。

坐标校正只发生在地图显示阶段，数据库始终保留 Apple 返回的原始加密坐标，因此已有历史不需要清除或重新采集。坐标只在应用内存中解密，不会生成明文轨迹文件。地图底图由 Apple MapKit 提供。

## 启用短信和通话归档

通讯内容不是从 iCloud 网页接口下载的。LifeTrack 只读取已经由 Apple“信息”和通话同步到这台 Mac 的本地数据库。

首次启用：

1. 确认 Mac 的“信息 → 设置 → iMessage”中已打开“启用 iCloud 云端信息”。要接收普通 SMS/MMS，还需要在 iPhone 上打开“短信转发”并允许这台 Mac。
2. 打开 **记录设置 → 通讯归档**。
3. 确认页面显示“完全磁盘访问：已授权”。如果显示“未授权”，点 **打开完全磁盘访问设置**，把 LifeTrack 加入允许列表并打开开关。
4. 回到 LifeTrack。应用会自动重新检查；确认状态变为“已授权”后，设置按钮会自动隐藏。
5. 点 **启用通讯归档**。

当前应用使用本地临时签名。升级重打包后，如果 LifeTrack 虽然仍显示为开启，但运行状态提示缺少权限，请在完全磁盘访问列表中移除 LifeTrack，再重新加入 `~/Applications/LifeTrack.app`，随后停止并重新开始后台记录。

首次启用时，LifeTrack 会导入当前仍存在于 Mac“信息”和通话历史数据库中的记录，随后后台约每 2 秒检查一次新增记录；位置采集仍使用单独的分钟级间隔。“导入现有记录”可以随时再次扫描全部系统记录，已经归档的内容会自动去重。

主界面顶部选择 **通讯归档**，可以：

- 查看收到和发出的短信、iMessage。
- 查看呼入、呼出、是否接通及通话时长。
- 按类型筛选和搜索本地归档。
- 查看原记录时间和 LifeTrack 归档时间。

归档成功后，即使 Apple“信息”或通话历史随后通过 iCloud 同步删除，LifeTrack 不会自动删除本地副本。附件文件目前不复制，只保存文字和“包含附件”标记。

这不是绝对无遗漏备份：Mac 关机、休眠、后台未运行、权限被撤销、内容没有同步到 Mac，或者记录在两次扫描之间极快地出现并删除时，都可能无法归档。重要数据仍应使用正式备份方案。

## 清除通讯归档

打开 **记录设置 → 通讯归档**，可以清除全部通讯、仅消息或仅通话。此操作只删除 LifeTrack 的本地加密副本，不会更改 Apple“信息”和通话历史。

## Apple 账户认证

第一次使用或登录会话失效时：

1. 打开 **记录设置**。
2. 点 **开始认证** 或 **重新认证**。
3. 在应用内输入 Apple 账户和密码。
4. Apple 会向受信任设备发送验证码；把六位验证码输入认证窗口。
5. 认证成功后，返回设置页选择设备并开始记录。

密码和验证码只通过本机进程管道传给认证程序，不会写入配置文件或命令参数。不要把密码或验证码发送到聊天、邮件或日志中。

点“重新认证”时，LifeTrack 会在旧会话的隔离副本中强制使用新输入的密码刷新登录。这样既不会跳过密码，又会保留 Apple 已授予的受信任浏览器标识，避免每次都被识别成陌生新设备。刷新会话只有在密码、双重认证和设备列表获取全部成功后才会替换旧会话。如果失败，界面会区分 Apple 登录拒绝、网络错误、验证码错误和“查找”会话被拒绝。未能主动向设备推送验证码不再被当成密码错误，仍可输入其他方式获取的六位验证码。

对 Apple 账户地区为中国大陆的账户，LifeTrack 使用 Apple 全球 `idmsa.apple.com` 完成密码认证，再通过 `icloud.com.cn` 和 `setup.icloud.com.cn` 访问中国区服务。这与本账户最初成功登录时的路由一致。
SRP 第一步返回的新 `scnt` 和 session ID 会被传递给第二步，不会继续沿用旧的一次性握手字段。

## 常见情况

“这个时间范围内没有位置”通常表示设备离线、Apple 仍在返回旧位置，或设备在所选时间内没有移动。它不一定表示记录程序出错。

如果窗口右上角显示“已停止”，打开 **记录设置** 并点 **开始记录**。如果设备刷新失败，先点 **重新认证**。

## 清除历史记录

打开 **记录设置 → 历史数据**，可以看到轨迹数量和本地存储占用。

数据管理支持：

- 永久保留全部轨迹。
- 自动只保留最近 30 天、90 天或 1 年。
- 清除全部设备的轨迹。
- 只清除指定设备的轨迹。
- 按位置时间限定需要清除的起止范围。

选择条件后点 **清除记录**，再在确认窗口中点 **永久清除**。

清除前，LifeTrack 会自动创建整个加密数据库的备份。Apple 认证、设备选择、采集间隔、自动保留期限和后台运行状态不受影响。如果后台仍在运行，清除后产生的新位置会继续保存。

“位置历史数据”区域会显示最近备份的时间、数量和大小。点击 **恢复最近备份…** 可以将轨迹和通讯归档恢复到最近一次清除前的状态。恢复会替换备份之后产生的数据，但 LifeTrack 会先为恢复前的当前状态再创建一个安全备份。自动备份最多保留 20 个，位于：

```text
~/Library/Application Support/LifeTrack/backups
```

## 数据与隐私

本地数据位于：

```text
~/Library/Application Support/LifeTrack
```

- `history.sqlite3`：历史数据库；设备信息、坐标、消息文字、号码、姓名和通话详情使用 AES-256-GCM 加密。
- `config.json`：采集间隔和不可逆设备短标识，不包含密码或坐标。
- `sessions/`：iCloud 登录会话，仅当前 Mac 用户可读取。
- `logs/`：后台运行日志，不记录 Apple 账户、原始设备 ID 或坐标。

轨迹主密钥保存在 macOS 钥匙串。本地数据库、会话、日志和后台服务配置都限制为当前用户访问，并可由 FileVault 进一步保护。
